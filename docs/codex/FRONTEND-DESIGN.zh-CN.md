# Codex 前端设计说明

日期：2026-10-06。本轮在“每个用户一个 Docker 个人环境”的运行模型上重新整理编程流程。本文描述设计来源、要解决的问题和本站实现范围；正式上线与验收结论以 [完整中文文档](README.zh-CN.md) 为准。

## 原页面的问题

首轮界面能完成项目和任务操作，但操作层级仍有改进空间：站点导航、工作台标题、环境条与项目信息重复占用纵向空间；所有内容都接近同一层级，任务回复、命令输出与状态提示容易混在一起；用户需要主动理解“工作区”和“容器”的实现关系；文件、差异、日志入口虽然齐全，从回复进入结果审阅的路径仍不够直接。手机上，多层横栏和工具区进一步压缩了会话与输入空间。

本轮应从用户实际流程验证：第一次进入能开始项目，重新进入能找到原任务；发送后能判断是否正在执行、需要确认还是失败；完成后能查看文件与变更；遇到断线、保存冲突或环境被占用时，能理解原因并保住草稿和未保存编辑。

## 页面组织与交互约束

用户主要面对“项目”和“任务”，个人环境只用于说明共用运行资源、当前占用和休眠状态。一个用户所有项目共用环境，但每个项目的文件和 Codex 会话分别保存。创建项目不应让用户选择 Docker 容器或填写宿主目录。

项目导航保留搜索、最近项目与归档入口，当前项目与正在执行的项目要容易识别。首页以输入任务作为起点，已有项目从“继续项目”或侧栏打开。新建项目提供空项目和公开 Git 仓库两种明确来源；仓库导入过程显示等待状态，输入出错保留已填内容。

会话以用户请求、公开助手回复和执行状态为主要阅读内容。命令、推理摘要、文件修改等详细过程可以展开检查；不得用折叠掩盖待确认请求、错误或尚未完成的工作。审批先展示理由、命令与目录或权限路径，原始请求 JSON 收入详情，减少无关代码占屏。自动滚动跟随最新内容，用户向上阅读时允许保持位置并通过最新消息入口返回。

输入区集中放置提示词、Code / Ask、模型与推理强度，窄屏参数工具栏单行横向滚动，发送和停止按钮保留独立触控位置。运行时保留草稿编辑能力，停止按钮清楚说明正在停止；发送失败保留原请求编号和草稿，不凭刷新页面重复执行任务。键盘发送应兼容中文输入法组合状态，换行和发送提示清楚。

结果面板围绕文件、变更和日志组织。文件默认查看，明确进入编辑后再保存；CodeMirror 编辑器提供行号、语法着色、保存快捷键和撤销/重做，按 Esc 后可用 Tab 移出焦点，有未保存内容时切文件或关闭需得到用户决定，版本冲突应保留本地编辑并允许下载。只读模式、其他项目正在占用环境、连接失败等情况要在操作处解释，不能只是留下不可点击的按钮。展示的差异来自实际项目内容和基线，不编造提交、测试或部署结果。

桌面保留可独立滚动的导航、会话与结果区域，会话和结果之间支持拖拽或键盘调整宽度；手机以会话和输入为主，项目列表与结果面板按需打开并能关闭。长文件路径、模型名、命令和多语言文字不应撑破页面；明暗主题、触屏目标、键盘焦点与可访问名称需要使用实际内容验收。

## 功能边界与验证

后端继续使用真实 Codex App Server `0.160.0` 与按用户隔离的 Docker 环境。仅管理员可访问，不增加收费、团队协作、任意交互终端、浏览器预览、GitHub 授权或多代理调度功能。只有已有接口支持且能实际完成的动作才进入界面。

组件测试覆盖草稿、发送停止、禁用与恢复、文件编辑和窄屏行为；构建前完成类型、目标文件 lint 和七语言检查。浏览器验收需使用本轮最终产物，覆盖实际登录、项目创建、多项目环境占用、Codex 执行、消息与工具过程、文件审阅、冲突、休眠恢复和移动端。首轮基础界面的 68 项浏览器结果不能替代重新设计后页面的验收；最终数字、截图和发布结果统一写入完整中文文档。
