# 开源源码与私有配置

公开源码使用示例域名和可配置的部署路径。生产环境文件、访问令牌、数据库密码、SSH 私钥、TLS 私钥、Codex 登录状态、日志、数据库与备份应存放在仓库之外。

`.env.example` 和 `.env.*.example` 一类示例只包含占位值；请复制为本地环境文件并生成自己的密钥。不要把示例值作为生产密码。仓库保留原项目及引用组件的许可证和版权声明。

## 提交前检查

安装 [Gitleaks](https://github.com/gitleaks/gitleaks)，在项目根目录执行：

```sh
gitleaks dir --config .gitleaks.toml --redact .
gitleaks git --config .gitleaks.toml --log-opts=--all --redact .
```

扫描配置只排除已核实的测试占位值和源码语法，不豁免整个测试目录。GitHub Actions 会扫描可达的完整 Git 历史。普通文本扫描不能代替压缩包、二进制、图片和已知生产凭据的核对；发布前应检查这些文件的实际格式。

## 历史清理后的协作

此仓库已为开源准备重写历史，移除证书包及个人部署信息，并将维护者的提交邮箱替换为 GitHub noreply 地址。旧提交 ID 会改变。协作者应重新克隆仓库，避免将旧分支、标签或补丁重新推送而带回已移除内容。

如果发现真实凭据进入版本库，应先撤销或更换该凭据，再清除所有分支和标签中的记录。仅删除当前文件不会删除 Git 历史；托管平台可能保留旧提交、缓存或其他引用，公开仓库前还应检查它们。已停用的证书与私钥不应重新用于部署。
