# 生图记录与预览

New API 转发的生图请求会自动显示在「任务 → 绘图」，不要求从在线 Codex 发起。

- Images 生成和编辑、Responses 的 `image_generation` 工具、Gemini 图片输出、兼容聊天和 Claude 格式中的图片输出均可记录。
- 已识别的生图请求显示连接和生成状态；模型别名无法预先识别时，在收到图片输出后自动建立记录。
- 流式部分图片不会计入完成数量。Responses 完成事件和最终响应中的同一图片不会重复计算；批量返回相同图片仍按实际输出项计数。
- 原有 Midjourney 任务保持原有列表与状态更新，计入绘图页正在生成的数量。
- 页面每 2 秒刷新活动任务，空闲时每 5 秒刷新。请求失败、断开或超过 3 分钟未更新的记录退出活动数量统计；正在执行的生图请求每分钟更新存活状态。
- 用户只能读取自己的记录和本地预览；管理员可在全部/仅本人范围间切换。记录不额外扣费，原接口响应与现有计费流程保持原样。

接口：

```text
GET /api/image-tasks?p=1&page_size=12&scope=self
GET /api/image-tasks/:id/images/:index
```

接口使用已有网站认证。`scope=all` 仅对管理员生效，图片资产使用认证请求下载，链接不包含账户凭据。

本地图片默认存储在 `./image-tasks`（生产 API 容器的 `/data/image-tasks` 持久目录），可通过 `IMAGE_TASK_STORAGE_DIR` 指定目录。每张图片最大 32 MiB，每个 JSON 响应或 SSE 数据行最多观察 64 MiB；超过限制的响应仍原样转发，但不会保存超限预览。外部图片 URL 由浏览器加载，New API 不代理抓取这些 URL。

新记录从部署后开始建立。历史生图请求不具备原始返回图片内容，不能自动补回预览。
